How to Code Sign,
Step by Step

A practical, hands-on walkthrough of digital signing on Linux — from hashing a file, to generating a signing key pair, to verifying the signature on the receiver side. Built from a real captured lab session.

By Ravi Dhungel·September 16, 2026·~10 min read

What a digital signature proves

Hashing alone is not signing. A SHA-256 hash proves integrity — but anyone can recompute a hash over a modified file. A signature binds the file's content to a private key, which is what proves origin.

🔍

Integrity

Was the file tampered with in transit? The hash inside the signature must match the file exactly.

✅

Authenticity

Did it really come from the claimed sender? Only the holder of the private key could have made it.

📜

Non-repudiation

Can the sender deny having sent it? No — the signature is cryptographic proof of authorship.

The lab setup

Sender works in ~/digitalsig, the receiver is simulated in ~/digitalsignreceiver, and the file being signed is a small bash script. Tools used: sha256sum, ssh-keygen (OpenSSH), and openssl.

1

Create the file to be signed

Sender
$ mkdir digitalsig && cd digitalsig
$ printf '#!/bin/bash\necho "hello world"\n' > helloworld.bash

Any file works — a script, a firmware binary, a document. The process is identical.

2

Make it executable and confirm it works

Sender
$ chmod +x helloworld.bash && ./helloworld.bash
hello world
3

Hash the file — your integrity baseline

Sender
$ sha256sum helloworld.bash > helloworld.bash.sha
$ cat helloworld.bash.sha
209cd8fc373c326107042208d0a738b737a543f8735e74a6873e51d5eaeea6b7  helloworld.bash

The .sha file stores the known-good hash. The receiver will recompute the hash and compare — a mismatch means the file changed. This detects tampering, but says nothing about who created the file. That is the signature's job.

4

Generate a signing key pair

Sender
$ ssh-keygen -t rsa -b 4096 -C "you@example.com"
$ ls ~/.ssh/
id_rsa  id_rsa.pub

-t rsa -b 4096 creates a 4096-bit RSA key pair — strong enough for long-term signatures. The private key (id_rsa) is the "pen" you sign with and must never be shared; the public key (id_rsa.pub) is what you give the receiver.

5

Sign the file with your private key

Sender
$ ssh-keygen -Y sign -f ~/.ssh/id_rsa -n file helloworld.bash
Signing file helloworld.bash
Write signature to helloworld.bash.sig

Under the hood: OpenSSH hashes the file (SHA-512) and encrypts that digest with your private key, writing the result to helloworld.bash.sig. The -n file flag is the namespace — it stops a signature made for one purpose from being replayed as another.

Real pitfall from the lab: openssl dgst -sha256 -sign ~/.ssh/id_rsa fails with "Could not find private key … EncryptedPrivateKeyInfo". OpenSSH's default private-key format is not readable by OpenSSL. Use ssh-keygen -Y sign for SSH keys, or convert to PEM first with ssh-keygen -p -m PEM -f ~/.ssh/id_rsa.
6

Deliver three things to the receiver

Handoff
ItemPurpose
helloworld.bashThe file itself
helloworld.bash.sigThe detached signature
helloworld.bash.shaThe hash baseline (integrity shortcut)
id_rsa.pubYour public key — via a channel the receiver already trusts

Trusting the public key is the whole ballgame: verification is worthless if the receiver got the attacker's key. Distribute public keys through a channel you already trust.

7

Receiver: verify the hash (quick integrity check)

Receiver
$ cd ../digitalsignreceiver/
$ sha256sum -c helloworld.bash.sha
helloworld.bash: OK

Confirms the file wasn't corrupted or altered in transit. Fast, simple — but it proves nothing about the sender.

8

Receiver: register the sender's public key

Receiver
$ echo "everest $(cat ~/.ssh/id_rsa.pub)" > allowed_signers

The allowed_signers file is the trust anchor: it declares that the identity everest may sign, and that this public key represents them.

9

Receiver: verify the signature — the moment of truth

Receiver
$ ssh-keygen -Y verify -f allowed_signers -I everest -n file \
    -s helloworld.bash.sig < helloworld.bash
Good "file" signature for everest with RSA key SHA256:Cxw+RrYYUXVZJun0iRRB1WkRTJjMXvdJ8Q1lEcoDsPg
FlagMeaning
-Y verifyVerify a signature instead of making one
-f allowed_signersThe trust file — which identities and keys you accept
-I everestThe claimed identity; must match a line in allowed_signers
-n fileNamespace — must be identical to signing time, blocks replay across contexts
-s helloworld.bash.sigThe detached signature file
< helloworld.bashThe file content, streamed on stdin (never modified)

That single Good line proves three things at once: the file is byte-identical to what was signed (integrity), it was signed by the holder of that specific RSA key (authenticity), and only that key holder could have produced it (non-repudiation).

Failure modes — any of these produce BAD instead of Good: a file modified after signing (even one byte), the wrong public key in allowed_signers, a namespace mismatch, or a signature copied from a different file.

Full command reference

Sender and receiver, in order — copy, paste, adapt.

# --- Sender ---
mkdir digitalsig && cd digitalsig
printf '#!/bin/bash\necho "hello world"\n' > helloworld.bash
chmod +x helloworld.bash && ./helloworld.bash
sha256sum helloworld.bash > helloworld.bash.sha
ssh-keygen -t rsa -b 4096 -C "you@example.com"
ssh-keygen -Y sign -f ~/.ssh/id_rsa -n file helloworld.bash

# --- Hand to receiver ---
# helloworld.bash, helloworld.bash.sig, helloworld.bash.sha, id_rsa.pub

# --- Receiver ---
sha256sum -c helloworld.bash.sha
echo "IDENTITY $(cat /path/to/sender_id_rsa.pub)" > allowed_signers
ssh-keygen -Y verify -f allowed_signers -I IDENTITY -n file \
    -s helloworld.bash.sig < helloworld.bash

Security notes from the lab

What the session taught us the hard way.

🔑

Use a passphrase

The lab's keys had none. In production, always set one — a passphrase-less private key is a skeleton key if the machine is compromised.

👁️

Don't print private keys

The session ran cat ~/.ssh/id_rsa, so the key now lives in the captured transcript. Rotate any key exposed this way.

🔄

Mind the key format

New-format OpenSSH private keys are unreadable to OpenSSL. Use ssh-keygen -Y sign for SSH keys, or convert to PEM for OpenSSL workflows.

🤝

Trust the key, not the signature

Verification is only as good as the channel that delivered the public key. An attacker with a substituted key verifies "perfectly".

⏱️

No timestamp here

This proves who and what, not when. For time-bound validity (certificates, contracts), use X.509 code signing with a CA and RFC 3161 timestamps.

🏥

Why it matters in MedTech

Firmware and software signing is a cornerstone of medical device cybersecurity — FDA premarket guidance expects integrity controls on device software. This is the primitive it all builds on.
